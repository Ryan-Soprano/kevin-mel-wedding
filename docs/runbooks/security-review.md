## Release acceptance

Run only against the approved environment with disposable synthetic fixtures. Record date, deployed commit, exact public origin, browser/OS and nonsensitive results on SEC-02. Do not retain raw requests, screenshots or copied diagnostics containing passwords, session cookies, CSRF/retry keys, signed permissions or guest content.

1. **Configuration and artifact:** confirm production profile/environment agreement, Secure cookies, exact HTTPS public origin, private throttle secret, closed reveal and private storage settings. Inspect the final built public artifact for privileged config or preview/test material. Local defaults must not identify a retained production database. Review actual application/proxy/access-log configuration and use synthetic marker failures to confirm secrets/content/capabilities do not appear in logs or errors. Preserve only redacted outcomes.
2. **HTTPS and forwarding:** verify the real public HTTPS request path, emitted cookie flags and redirect/HTTP behavior through the actual approved proxy. An unapproved Origin/cross-site session or review mutation must be refused. Validate the captured peer boundary under actual forwarding and ensure the internal application port is not exposed directly. Do not treat an inspected Secure flag on local HTTP as deployed proof.
3. **Private routes and CSRF:** use separate synthetic anonymous, COUPLE, OPERATOR and DEVELOPER cases, with reveal open only for the exercise. Anonymous/capability/role-only knowledge must not return private inbox/detail/playback content. Session and review mutations require current CSRF; pre-login and logged-out tokens must fail. Reset/disable and closed reveal must prevent subsequent protected access and new playback issuance. Passing staging admission must not grant couple authority.
4. **Storage:** verify the actual bucket has no public `r2.dev` or custom domain, unsigned original/staging GET and HEAD fail, and the backend token is limited to the intended bucket. Confirm exact approved-origin PUT/GET/HEAD CORS and disallowed-origin refusal. Upload/finalize a synthetic supported photo; verify the original's bytes/MIME/hash, precise scope and real expiry. Omit app credentials/referrers for browser media fetch. Do not use a public bucket or wildcard as a CORS fix.
5. **Caching and shared devices:** inspect actual API, error and media cache headers through the proxy. Sign in, display synthetic text/photo, sign out, then exercise Back/Forward, refresh, another tab and a guest return. Private rows/details and owned previews must remain hidden without current authorization. Repeat with slow/late requests, a lost logout response, hidden-tab/tab-return or Back/Forward cache, idle expiry, account revocation and a pending/uncertain review. A failed sign-out must remain visibly unconfirmed and offer recovery before leaving the device. Use actual iPhone Safari and assigned Android Chrome for the relevant browser cases.
6. **Bearer boundary and downloads:** verify logout/recovery/disable/reveal closure blocks new links while a previously issued permission remains usable only until its own expiry. A saved original or screenshot cannot be reclaimed by sign-out. Use a private personal session for couple viewing; do not leave downloads, saved passwords or an unconfirmed active session on a shared device.
7. **Close the record:** attach nonsensitive outcomes to SEC-02 and update the register below. A local test pass cannot close a hosted/device row. Restore closed reveal and remove only owned synthetic fixtures using the existing recovery/retention procedure; do not reset a retained database.
