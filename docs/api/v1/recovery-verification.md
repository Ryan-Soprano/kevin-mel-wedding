## Important boundaries

The package contains raw guest retry capabilities and private guest content. It excludes credentials/accounts, sessions, throttle counters, application settings and temporary staging bytes. It is privileged archive-data recovery material; it cannot substitute for a full database backup or establish wedding-window five-minute database RPO by itself.

Repeatable-read makes database rows consistent but cannot freeze live provider IO. `MEMORY_ARCHIVE_RECOVERY_QUIESCED=true` and console confirmation assert operator readiness; they do not remotely stop a different application. Stop collection/private traffic, finalization and maintenance, then wait for every issued grant to expire. Pending/failed intents remain unfinished; a restored receipt must not invent a saved original.

Every restore reads the current authoritative independent ledger and requires all packaged records to survive unchanged. It binds that authority to the originating storage identity and rejects future/malformed/identity-conflicting evidence. Replay scrubs newer erased notes/captions/media and reserves submission-key digests even for contributions absent from the backup. Unrelated sibling memories remain intact. Source authority writes/deletes are mechanically forbidden in the console.

The original authoritative source endpoint/bucket must be available or reconstructed with complete current evidence. A ledger copy relocated to another bucket cannot directly satisfy the bound identity in this version; total source-loss recovery from that relocated authority remains unsupported. The completed independent archive-copy restoration below still used the original current authority. The recovery console does not schedule exports or expire packages; separately reviewed operator policy/tooling owns the 30-day retention limit.

Preflight errors make no target mutation. Storage errors can leave partial isolated object copies or ledger writes even when database import rolls back. Keep traffic stopped, inspect the actual target privately and retry only when the database remains empty and existing copied originals match. Never clear a populated target after an uncertain commit.

Package v2 exports exact reviewed V9 databases and uses generic pending/failed media counts. Exact reviewed V8 packages keep their strict v1 schema, photo-only fields and original fingerprint. V9 targets may restore that v1 package with null new audio columns; V8 targets reject v2. Rehashing a v1 package cannot add AUDIO support. Later packages add authorship/metadata (v3/V10), albums (v4/V11), timeline (v5/V12), tags (v6/V13) and memory/review-audit audiences (v7/V14). Each version requires its reviewed schema or a supported newer target. Unknown versions/fields, altered reviewed history or unsupported column names/types/nullability are rejected before target changes.

V14 recovery deliberately excludes private-link token digests and requires the destination's `memory_share_link` table to be empty. The couple must issue new links after recovery. Older v1–v6 packages restore into V14 with `COUPLE_ONLY` memory and audit audiences. Current independent deletion replay remains authoritative over restored content and organization. The [operator runbook](../../runbooks/operator-recovery.md) describes the complete version matrix and schema-check limits.

Audio originals are checked for size/SHA-256 and decoded again before export, before restore mutation, and after publication. Stored verified millisecond duration, container and codec must exactly match the original; the guest duration claim remains separate. Synthetic tone fixtures exercise WebM/Opus, Ogg/Opus and MP4/AAC preservation, pending/failed reservations, changed hash and rehashed duration rejection, current-ledger audio erasure, absent-key reservations and V8-to-V9 compatibility. Full integrated validation is recorded in the AUD-03 verification record after its checks complete.
