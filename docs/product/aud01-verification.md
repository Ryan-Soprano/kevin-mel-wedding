## What is prepared and locally checked

- Source: `frontend/spikes/audio/`, outside the normal Vite entry/public assets. Normal frontend production output contains no probe page or probe assets. `Dockerfile` and `scripts/build-app.sh` copy only its HTML/JS/CSS into private classpath `staging-audio/`; the `.test.mjs` file is excluded.
- The controller and its exact five GET paths exist only with the `staging` profile. The existing temporary staging HTTPS/Basic admission remains mandatory. Non-staging requests cannot retrieve the page, modules, CSS or private classpath source. Responses are `no-store`; the page's CSP uses **`connect-src 'none'`**, permitting local Blob replay while preventing upload/fetch connections.
- Microphone permission is requested only after **Start recording** is clicked. Nothing auto-records or auto-submits. Type negotiation uses runtime `MediaRecorder.isTypeSupported` hints, attempts recorder construction, then falls back to the browser's default recorder. Capability and MIME labels are not format approval.
- Record, stop, local replay and discard are implemented. Stop/discard/error/background/navigation release tracks; discard/navigation revoke audio URLs. A generation guard prevents late callbacks or permission/decode results from a previous attempt from replacing a new one. Denied/unsupported/unavailable/interrupted/invalid states offer an existing-file check and written-note link.
- One clip is accepted locally only when it is nonempty, **at most 25,000,000 bytes**, decodes locally, and its actual decoded duration is **at most 120 seconds**. A capture timer stops before two minutes to leave encoder finishing time; chunk overflow discards incomplete bytes. A delayed/background timer cannot approve an overlong decoded clip. These are probe checks, not server enforcement or a production audio API.
- Results distinguish requested recorder MIME, recorder-reported MIME, Blob MIME, a byte-derived container observation and successful local audio decoding. They include decoded duration, capture wall time, size, channels/sample rate and SHA-256 when Web Crypto is available. The signal-check-1 diagnostic revision also measures decoded peak/RMS levels, exact digital silence and a clearly labeled low-level warning; it records only safe track state and mute/unmute events. No PCM samples, track/device identifiers or microphone labels are exported. Unknown container observations remain unapproved; no MIME hint, filename or local replay alone establishes the final server allowlist.
- **Download results JSON** exports only technical measurements, manually entered device/version and pass/fail observations. It contains no audio, filename, capability, credentials or raw user agent. **Download synthetic test clip** is a separate explicit click that saves the same local validated Blob with a deterministic container-based extension (or `.bin` when unconfirmed). It never transfers the clip to another device or server; Ryan performs any approved test-device transfer himself.
- **20 focused frontend tests and the full 96-test frontend suite pass**, covering timer receiver binding, explicit-only permission, denial/retry, stale permission/error/track/mute callbacks, stop-before-validation, MIME-constructor fallback, interruption, byte/duration boundaries, decode cancellation, URL disposal, SHA-256, byte/container observations, multichannel signal measurements, exact silence/non-finite PCM, and offline/failed decoder cleanup. **Two HTTP tests passed** for staging admission/CSP/exact routes and non-staging exclusion in the earlier combined verification; their backend paths are unchanged by diagnostics. ESLint and the normal frontend production build pass. The coordinator tests use synthetic recorder/decoder doubles; they do not verify a physical microphone or a browser codec.
