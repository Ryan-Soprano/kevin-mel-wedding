## Candidate changes

1. **Production startup:** [production properties](../../backend/src/main/resources/application-production.properties) now carry the measured Render port/bind/proxy and one-finalizer settings, Secure cookies and required DB variables. Changing profiles no longer silently drops those safeguards or supplies local DB defaults. Profile/environment must still both be `production`, and actual provider overrides must be checked privately.
2. **Private draft recovery:** [couple submission adapter](../../frontend/src/features/inbox/api/coupleSubmissionApi.js) refreshes a stale CSRF token without automatically replaying the rejected write. The current creator retains its draft/files/key for explicit retry. Real access loss, failed/anonymous/observably changed-owner refresh and obsolete callbacks remain fenced. Fifteen regressions were added to the existing [couple-memory tests](../../frontend/src/features/inbox/api/coupleMemories.test.js); no new tracked test file was introduced. Owner checks use the existing session reference/generation/display name/roles, not an invented stable account ID.
3. **Dependency security:** Vite is patched from 8.3.0 to **8.3.3** with its lockfile. Current upstream advisories affect the editor integration used by the development toolchain; the runtime remains the combined Spring app. See the [Windows path-check advisory](https://github.com/advisories/GHSA-587h-7wmj-h5pm), [argument-escaping advisory](https://github.com/advisories/GHSA-698v-4r3x-3vcv) and [editor-flag advisory](https://github.com/advisories/GHSA-r825-w8mm-5pxw). No cosmetic Sonar cleanup or API/media-limit changes are included.
4. **Rollback:** the guide now explicitly requires reveal closed and anonymous private-access denial before reopening an older deploy. Historical staging settings must not silently reopen tester access or restore the wrong origin.
5. **Reliable verification:** existing Vite SSR tests now use process/file-specific optimizer caches. This removes a Windows cache-directory rename collision exposed by the patched Vite release, without changing production optimization or adding test files.

## Failure and contingency review

| Trigger | Expected response / verification |
| --- | --- |
| Lost CREATE/finalize response or double tap | Reconcile receipt; retry the same body/file/item/key. A new intent is a deliberate new submission. Check stable IDs and no duplicate publication. |
| Partial photo batch / busy decoder | Keep saved siblings; retry only unfinished items using retained identity and honor `Retry-After`. The hosted burst needed recovery for 43/99 initial groups. |
| 429 / shared network | Honor the returned wait and preserve the draft. Retry-key cooldown passed; shared-parent denial/recovery still needs evidence. |
| Microphone denied, interrupted or unsupported file | Clear recording indicators/tracks, keep truthful failure/fallback, and use a supported existing file or text. HEIC remains rejected with guidance; contract sizes/durations stay unchanged. |
| R2 outage / invalid original / full reservation budget | Never acknowledge a saved original before verification/commit. Inspect private readiness/provider metrics. Media upload pause stops new intents/grants, while notes, existing grants and recovery may continue. |
| Duplicate grants behind slow finalization | The local probe shows unrelated requests can queue on the same pool. Preserve identity/receipt recovery; use maintenance if collection becomes persistently unavailable. Do not blindly enlarge the pool or decoder concurrency. |
| Process restart / deployment | Durable receipts and originals survive on the retained DB/bucket; in-memory sessions and temporary export jobs may expire. Keep recovery truthful and test known intent replay. |
| Old deploy rollback | Keep current DB/R2/ledger, canonical origin and reveal false. Verify schema compatibility, profile/admission, private denial and receipts before reopening. Never restore a prelaunch DB over new memories. |
| Domain/TLS routing failure | Keep collection stopped, repair the association/DNS or restore the recorded Coming Soon mapping. The fallback is a holding page; cached/open clients may still have failed receipts/retries. |
| Private CSRF or actual access loss | Stale CSRF refresh preserves an owned draft for explicit retry. True access loss clears private state. Already issued signed links retain their documented short expiry semantics. |
| Backup/ledger unconfirmed or privacy exposure | Keep recovery/collection closed as applicable; preserve current authority and investigate with private evidence. Do not improvise destructive cleanup. |

For local checks, do not run `smoke-packaged-app.mjs` in a shell carrying live DB credentials: startup can run Flyway and its invalid request updates throttle state. Use isolated Docker fixtures. When using `smoke-reception.mjs`, supply `--image` with the current complete immutable image ID; its built-in default is historical.
